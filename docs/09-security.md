## 인증
- 비밀번호는 BCrypt. 로그인 실패 문구는 "없는 계정"과 "틀린 비밀번호"를 구분하지 않고, 없는 계정이어도 해시 비교를 똑같이 해서 응답 시간으로도 구분하지 못하게 했다.
- **로그인 실패 제한**: 한 계정에서 15분에 10번 틀리면 맞는 비밀번호로도 429 (여러 IP 에서 돌려 가며 노리는 경우).
- **IP 별 제한**(10분): 로그인 60, 가입 20, 토큰 갱신 120. 공용 IP(학교)를 생각해 넉넉하게 뒀다. 초과하면 429 와 `Retry-After`.
  - IP 는 Cloudflare 가 채우는 `CF-Connecting-IP` 를 쓴다. 클라이언트가 마음대로 붙일 수 있는 `X-Forwarded-For` 는 믿지 않는다.
- **비밀번호 변경**: 현재 비밀번호를 15분에 5번까지만 틀릴 수 있고, 바꾸면 그 계정의 로그인 유지 토큰(refresh)을 모두 지운다. 화면은 이 기기도 다시 로그인시킨다.
- 로그인 유지 토큰은 사용할 때마다 새것으로 바뀌고(회전), DB 에는 해시만 있다.
- JWT 서명 키는 32바이트 미만이면 서버가 뜨지 않는다.

## 입력
- **저장형 XSS 차단**: 크레딧 링크처럼 사용자가 적고 `<a href>` 로 쓰이는 주소는 서버가 `http://`·`https://` 만 받고(`@HttpUrl`), 화면도 `safeHttpUrl` 로 한 번 더 거른다. `javascript:`·`data:`·`//host`·공백이 섞인 우회(`java\tscript:`)는 모두 거절한다. 이미 저장된 값이 있어도 화면에서 링크가 되지 않는다.
- 채팅·댓글·닉네임은 React 가 글자로만 그린다. `dangerouslySetInnerHTML`·`innerHTML` 은 쓰지 않는다.
- 채팅 도배: 슬로우 모드를 꺼 둔 방송에서도 한 사람이 10초에 10번까지만 보낼 수 있다(채널 주인·매니저 제외, 후원 제외).

## 실시간 채팅(WebSocket)
- 채팅방 구독은 **허용 목록**(`/topic/lives/{숫자}`, `/events`, `/viewers`, `/user/queue/*`)만 된다. 단순 브로커는 `/topic/lives/*` 같은 와일드카드 구독을 받아 주므로, 막지 않으면 구독자 전용 방송의 채팅을 통째로 엿볼 수 있었다(점검 중 찾아 고침).
- 구독자·유료 구독자 전용 방송은 구독 시점에 자격을 확인한다. 비로그인은 연결만 되고 보내기는 못 한다.
- 오리진은 허용한 화면 주소만 핸드셰이크할 수 있다.

## 업로드
- 확장자 허용 목록(영상 mp4·mov·webm·m4v·mkv, 이미지 jpg·png·webp·gif)만 받고, 이름은 서버가 uuid 로 새로 만든다(경로 이동 불가). SVG·HTML 은 받지 않는다.
- 파일은 API 와 **다른 주소(origin)** 에서 서빙되고 `X-Content-Type-Options: nosniff` 가 붙는다.
- 로그인한 사용자만 올릴 수 있고, 파일 하나 최대 100MB.

## 서버·헤더
- API 응답: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, HSTS, `Cache-Control: no-store`. CORS 는 허용한 화면 주소만.
- 웹(Vercel): `vercel.json` 에서 `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`(카메라·마이크·화면 공유는 이 사이트만), `Content-Security-Policy: frame-ancestors 'none'; base-uri 'self'; object-src 'none'` 을 붙인다.
- 운영에서 Swagger·API 문서는 꺼져 있다(`SWAGGER_ENABLED`). 내부 콜백(`/api/internal/**`)은 비밀 값이 없으면 403.
- 에러 응답에 스택 트레이스를 싣지 않는다.
- 컨테이너는 root 가 아닌 사용자로 돈다.

## 개발·배포 과정
- 비밀 값(JWT 키, 토스 시크릿, DB 비밀번호, 스트림 키)은 저장소에 없고 환경변수로만 준다. 저장소 전체를 검색해 키·토큰 모양의 값이 없음을 확인했다.
- CI 워크플로는 `contents: read` 만 가진다. 서버 깨우기 워크플로는 권한이 없다.
- **CodeQL**(Java·JavaScript 정적 분석)이 푸시·PR·매주 돈다. 결과는 저장소의 Security → Code scanning.
- **Dependabot**이 달마다 의존성 보안 업데이트를 PR 로 제안한다(gradle·npm·docker·actions).
- `npm audit --omit=dev` 취약점 0건(2026-10-13).

## 알려진 한계 (일부러 두었거나 못 한 것)
- **토큰이 브라우저 localStorage 에 있다.** XSS 가 한 번 뚫리면 토큰이 새는 구조다. 쿠키(HttpOnly)로 옮기려면 CSRF 방어와 도메인 구성이 같이 바뀌어야 해서 이번에는 하지 않았다. 대신 XSS 입구(사용자 링크)를 막고 CSP·헤더를 붙였다.
- **액세스 토큰은 만료(기본 1시간)까지 쓸 수 있다.** 로그아웃·비밀번호 변경은 로그인 유지 토큰만 지운다. 즉시 폐기하려면 서버에 토큰 목록(블랙리스트)이 필요하다.
- **제한 횟수는 서버 메모리에 있다.** 서버가 재시작되면 초기화되고, 여러 대로 늘리면 Redis 가 필요하다(슬로우 모드·시청자 수와 같은 가정).
- 업로드는 확장자만 보고 파일 내용(매직 바이트)은 검사하지 않는다. 다른 origin 서빙 + nosniff 로 영향을 줄였다.
- 전체 CSP(스크립트·연결 허용 목록)는 토스 결제창·HLS·웹소켓을 깨뜨릴 수 있어 넣지 않았다. 위험이 큰 `frame-ancestors`·`base-uri`·`object-src` 만 넣었다.
- 비밀번호 재설정(이메일), 이메일 인증, 2단계 인증은 없다.
- 후원·구독 결제는 테스트 키다. 실제 결제로 옮기려면 토스 가맹 심사와 웹훅 주소 등록, 운영 키 교체가 필요하다.
