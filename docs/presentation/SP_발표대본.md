# SP 발표 대본

슬라이드마다 말할 내용입니다. (PPT 파일에는 노트가 들어 있지 않습니다)

## 1. 표지

안녕하세요. 제가 만든 SP 입니다. SP 는 방송을 실시간으로 보고 채팅·구독·후원까지 되는 라이브 중심 스트리밍 플랫폼이고, 웹·API·DB 를 모두 무료 구간에 배포해 지금 주소로 접속해 볼 수 있습니다.

## 2. 주제를 바꾼 이유

처음에는 클라이밍 완등 기록 앱을 계획했지만, 7월 29일부터 만들어 온 SP 가 이미 배포 단계까지 와 있었습니다. 새로 시작하는 것보다 이쪽을 서비스 수준으로 끌어올리는 게 더 의미 있다고 판단해 주제를 바꿨습니다.

## 3. 핵심 기능

핵심 기능은 세 가지입니다. 방송을 보고, 실시간 채팅으로 이야기하고, 구독과 후원으로 지원하는 흐름입니다. 결제는 토스페이먼츠 테스트 키를 써서 실제 청구는 없습니다.

## 4. 홈 화면

홈 화면입니다. 위쪽은 지금 방송 중인 것을 크게 보여 주는 어두운 슬라이더이고, 아래쪽은 카테고리 칩과 영상 카드 격자입니다. 밤 모드와 낮 모드가 같은 그린과 퍼플 색을 씁니다. 운영 사이트는 비어 보이지 않게 데모 채널과 영상을 넣었고, 데모라고 표시했습니다.

## 5. 시청 화면

시청 화면의 아래쪽은 제목, 채널 줄, 반응, 설명, 댓글 순서로 한 줄에 한 가지 일만 하도록 정리했습니다. 한계도 숨기지 않으려고, 소리가 안 들어가거나 서버가 잠들어 느릴 때 화면이 이유와 해결 방법을 알려 줍니다.

## 6. 방송 방식

운영 서버인 Render 무료 서버는 RTMP 를 받지 못합니다. 그래서 운영 사이트에서는 웹의 방송하기로 누구나 방송할 수 있게 했고, OBS 로 방송할 때는 내 PC 가 스트리밍 서버가 되고 시청 주소만 임시 터널로 공개합니다. OBS 방송은 시청이 HLS 라서 지연이 7초에서 10초 정도이고, 웹 방송은 저지연으로 보면 Chrome 에서 약 1초, 일반 재생으로 보면 7초에서 10초입니다.

## 7. 구조

웹은 Vercel, API 는 Render, DB 는 TiDB Cloud 에 모두 무료로 올렸습니다. 웹 방송은 방송자의 브라우저가 H.264 로 녹화한 조각을 WebSocket 으로 보내면, 서버의 ffmpeg 가 다시 인코딩하지 않고 HLS 로 포장만 바꿔 내려 줍니다. 서버가 영상을 처리하지 않아서 0.1 CPU 의 무료 서버로도 방송 한 개가 됩니다.

## 8. 숫자로 보면

규모를 숫자로 보면, 백엔드 자동 테스트 386개가 전부 통과하고, 데이터베이스 표는 22개이며, 웹·API·DB 세 곳을 모두 무료로 배포했습니다. 구독은 1·3·6·12개월 기간 상품이 있습니다.

## 9. 운영에서 부딪힌 문제

운영에 올리고 나서 부딪힌 문제 세 가지입니다. 첫째, 4K 영상을 올리면 썸네일을 뽑는 ffmpeg 가 메모리를 넘겨 서버가 죽었고, 메모리를 약 511MB 에서 52MB 로 줄였습니다. 둘째, 데모 데이터 마이그레이션이 CI 는 통과했지만 운영 DB 인 TiDB 의 정렬 규칙 검사에 걸렸습니다. 셋째, Render 무료 디스크가 임시라 재시작하면 업로드가 사라져서 DB 에 사본을 두었습니다.

## 10. 저지연 판단

방송 지연을 줄이려고 저지연 중계를 만들었고, 운영 사이트에서 Chrome 으로 직접 써 보니 지연이 약 1초로 매우 빨랐습니다. 로컬에서 여러 명이 볼 때 잰 값은 1.6초에서 1.8초입니다. 그런데 화질은 달라지지 않았습니다. 받는 영상은 1920 곱하기 1080 인데도 저지연이든 일반 재생이든 글자가 똑같이 번졌습니다. 서버가 영상을 다시 인코딩하지 않기 때문에 화질은 방송하는 브라우저가 만든 영상이 정하고, 지연과 화질은 별개의 문제라는 걸 확인했습니다. 무료 서버가 못 버틸 때를 대비해 관리자 화면에 서버를 다시 켜지 않고 켜고 끄는 스위치를 넣었습니다.

## 11. AI 활용

AI 는 로컬 AI 인 Workbench 와 Claude Code 를 썼습니다. Workbench 는 계획서를 만들고 다듬는 데, Claude Code 는 코드와 테스트, 문서, 원인 분석에 썼습니다. 어떤 디자인으로 갈지, 주제를 SP 로 바꿀지, 무료 배포를 어떻게 구성할지, 어떤 문제를 먼저 고칠지는 제가 정했고 결제 승인과 영상 업로드, 소리 포함 방송도 직접 확인했습니다. AI 가 틀린 적도 있었는데, 서버가 잠들어서 느리다고 진단했지만 실제 원인은 썸네일 ffmpeg 의 메모리 초과였고 확인해서 바로잡았습니다.

## 12. 한계

모두 무료 구간이라 한계가 있습니다. Render 서버는 15분 동안 접속이 없으면 잠들어서 첫 요청이 최대 3분쯤 걸립니다. 그래서 화면에 서버를 깨우는 중이라는 안내를 띄우고, 깨어나면 자동으로 이어지게 했으며 10분마다 서버를 깨우는 작업도 돌립니다. 웹 방송은 Chrome 과 Edge 만 되고 동시 방송은 한 개이며 다시보기가 없습니다. OBS 방송은 저지연이 없어서 지연이 7초에서 10초입니다. 시청자 수 같은 집계는 서버 메모리라 서버를 여러 대로 늘리려면 Redis 가 필요합니다.

## 13. 마무리

이상으로 발표를 마치겠습니다. 지금 주소로 접속해서 직접 써 보실 수 있고, 서버가 잠들어 있으면 첫 접속이 느릴 수 있습니다. 감사합니다.
