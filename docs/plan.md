# 계획 설계서 (plan.md)

## 0.주제 변경 사유
처음에는 클라이밍 완등 기록 웹앱을 계획했지만, 2026-07-29부터 만들어 온 라이브 스트리밍 플랫폼(SP)이 이미 배포 단계까지 와 있어서 이쪽을 완성도 높이는 쪽으로 바꿨다.
처음부터 새로 만들기보다 실제 서비스 수준으로 끌어올리는 쪽이 남은 시간에 더 의미 있다고 판단했다.

## 1.한 줄 소개
방송을 실시간으로 보고 채팅·구독·후원까지 되는 라이브 중심 스트리밍 플랫폼. 웹은 Vercel, API는 Render, DB는 TiDB(MySQL 호환)에 무료로 배포했다.

## 2.누구를 위한 것인가
방송을 하며 채팅 운영과 구독·후원 수익을 관리하고 싶은 개인 스트리머(OBS 로 송출하거나, 웹의 "방송하기"로 PC 설치 없이 바로 방송), 채널을 구독하고 라이브 채팅에 참여하며 다시보기로 보고 싶은 시청자.

## 3.핵심 기능 3가지
1. **라이브 방송·시청:** OBS(RTMP→HLS) 방송, 웹에서 화면 공유/카메라로 바로 방송, 방송 예약·대기실, 다시보기와 채팅 리플레이.
   - 웹 방송은 브라우저가 WebSocket(`/ingest`)으로 영상 조각을 보내면 서버의 ffmpeg 가 다시 인코딩하지 않고 HLS 로 포장만 바꿔 내려 준다(Chrome·Edge, H.264 녹화 필요).
2. **실시간 채팅과 운영:** WebSocket 채팅, 매니저·금칙어·채팅 제한·슬로우 모드·공지 고정.
3. **수익화:** 토스페이먼츠 테스트 키로 유료 구독(1·3·6·12개월)·후원·환불·정산 내역, 멤버십 전용 방송.

## 5.이번 버전에서 바뀐 것
- 화면 전체를 시네마틱 디자인으로 바꿈: 떠 있는 유리 독과 머리 줄, 나뭇잎 모양 얼굴·카드, 밤·낮 두 팔레트, 홈은 큰 화면 + 필름스트립 + 곧 시작하는 방송
- 첫 화면 스켈레톤(자바스크립트가 오기 전 나뭇잎 모양 뼈대), 좁은 화면에서도 나뭇잎 곡률 유지, 키보드 Tab 이동 때의 포커스 링
- 유료 구독 기간 상품(1·3·6·12개월, 오래 구독할수록 할인) 추가
- 좋아요(하트)를 방송마다 따로 기억하도록 수정
- 서버 시각이 9시간 어긋나던 표시 수정
- 카드 결제 후 돌아올 때 404가 뜨던 문제 수정(폰에 뜨는 `toss.im` 404는 토스 화면이라 결제창에 안내 문구만 둠)
- 웹 방송에서 소리가 안 들어갈 때 이유와 해결법을 화면에 안내
- 4K 영상 업로드 때 서버 메모리가 넘쳐 죽던 문제 수정(썸네일 추출 메모리 약 511MB → 52MB), 잠든 서버 안내와 자동 복구, 10분마다 서버 깨우기
- 서버가 재시작하면 올린 영상·이미지가 사라지던 문제 수정(파일 사본을 DB 에 보관하고 요청 때 되살림), 깨진 오시마크 이미지는 그리지 않음

## 7.알려진 한계
- 무료 서버(Render)라 15분 무접속이면 잠들어 첫 요청이 느리고(최대 약 3분), RTMP 를 받을 수 없다. 그래서 운영 방송은 두 가지다.
  - **웹 방송**(PC 불필요): 다시보기 없음, 동시 방송 1개(메모리 512MB), 시청자 적은 시연용, 탭을 닫으면 방송 종료, 시청 지연 약 10초.
  - **OBS 방송**: 내 PC 가 스트리밍 서버가 되고 시청용 포트만 임시 터널로 공개한다. 방송할 때마다 스크립트를 켜야 하고, Render 가 재시작하면 방송을 다시 시작해야 한다.
- 웹 방송은 H.264 로 녹화되는 Chrome·Edge 에서만 되고, 화면 공유에는 소리가 안 들어가는 경우가 많다(마이크 포함 옵션으로 보완).
- 업로드 파일은 DB(TiDB 무료 5GiB)에 사본을 두므로 용량을 같이 쓰고, 파일 하나는 최대 100MB 다.
- 슬로우 모드·시청자 수는 서버 메모리 기반이라 서버를 여러 대로 늘리기 어렵다(Redis 필요).
